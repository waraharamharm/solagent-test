# Security

## Приложение

| Что | Как |
|---|---|
| Секреты | `flutter_secure_storage`: пароль и ключ сервера, ключ ИИ, ключ RAG. Наружу не уходят |
| Вход | Экраны сервера, развёртывания и подтверждения закрыты биометрией или PIN устройства (`local_auth`). Без блокировки экрана доступ закрыт, при уходе в фон блокировка возвращается |
| Сервер | Отпечаток хоста запоминается при первом подключении (TOFU) и проверяется дальше; чужой отпечаток отклоняется |
| Память | После входа Dart-объекты с паролем зануляются (`credential.wipe()`) |
| Очистка | `LogRedactor` (в изоляте): IP, хост, логин, пути, токены, пароли `key=value`, флаги CLI, URL с логинами, ключи (PEM, `AKIA…`, `AIza…`, `xox…`), e-mail |
| Команды | `CommandPolicy`: разрушительные запрещены, остальные с предупреждением. Решение всегда за пользователем |

## Недоверенные данные

Для ИИ недоверенными считаются лог сервера, фрагменты из RAG и журнал с
сервера. Они стоят в промпте в блоках `<log>`, `<knowledge>`, `<history>`,
системный промпт говорит, что это данные, а не инструкции. Теги в содержимом
нейтрализуются. Журнал на сервере можно править руками, поэтому доверия ему нет.

## RAG-сервер

- Ключ `Bearer sol_…`, в базе только sha256.
- Лимиты и 429, лимит тела, очередь модерации: [RAG_SERVER.md](RAG_SERVER.md).
- Решения от клиентов очищаются при приёме, секрет после очистки → `422`.
- В поиск решение попадает только после ручной модерации через CLI.
- `/v1/health` отдаёт только `{"status":"ok"}`.
- Ошибки только в JSON `{status, code, message}`, без эха входных данных.

## Знания

Знания собраны из чужого приватного репозитория, в котором были настоящие
секреты. Копия строится по белому списку корней, все тексты чистятся и
проверяются до записи; при любой утечке сборка отказывает. Независимая проверка
(`data/verify.py`) берёт значения из сырого исходника: 0 утечек.
Репозиторий знаний приватный, история не переносится.
