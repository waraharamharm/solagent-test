# Architecture

Flutter, Riverpod 3 с кодогенерацией (`@riverpod`), `go_router`, `gen-l10n`
(ARB, шаблон `en`), `dio`, `dartssh2`, `flutter_secure_storage`, `local_auth`.

Слои внутри фичи: `domain` (модели, интерфейсы) → `data` (реализации) →
`application` (провайдеры, контроллеры) → `presentation` (экраны). Структура
папок: [../LAYOUT.md](../LAYOUT.md).

## Развёртывание на сервере (`features/deploy`)

Задача запускается на самом сервере отдельным процессом (`setsid nohup`) в
`~/.solagent/jobs/<id>/`, обрыв SSH её не убивает. Прогресс читается по номеру
строки лога. Состояния: `running`, `finished`, `cancelled`, `lost`, `unknown`.
После перезагрузки сервера задача `lost`.

## Цикл самоисправления (`features/fix`)

1. Запуск скрипта.
2. Код выхода не 0 → лог очищается (`LogRedactor`) → ИИ получает его как
   недоверенные данные и отвечает JSON: диагноз, одна команда, пояснение.
3. `CommandPolicy` проверяет команду: запрещённые не показываются (ИИ получает
   отказ), опасные идут с предупреждением.
4. Пользователь подтверждает или отклоняет. Подтверждённая команда выполняется
   ровно в том виде, как показана (`set -e`, задача `<id>-fN`).
5. Исходный скрипт запускается заново (`<id>-rN`). Не больше 3 раундов.

Кто за что отвечает:

| Класс | Роль |
|---|---|
| `FixLoop` | сам цикл, события `FixEvent` |
| `FixAdvisor` | промпт, разбор ответа ИИ, `<history>` и `<knowledge>` |
| `FixSessionFactory` | открывает сервер: SSH, проверка ОС, журнал, RAG, сборка `FixLoop` |
| `FixRun` | состояние для экранов, ответ пользователя, запись в журнал |
| `journalEntryFor` | что именно писать в журнал по событию |

`FixRun` не знает про SSH: тесты подменяют `FixSessionFactory`
(`test/features/fix/fix_run_controller_test.dart`).

## ИИ (`features/llm`)

Интерфейс `ILLMService`, реализация OpenAI-совместимая
(`/v1/chat/completions`). Пресеты: DeepSeek, Grok, OpenRouter, OpenAI, свой
адрес. Адрес должен быть `https` (`http` только для локальных адресов).
Ключ в `SecureStore`. 401 и 403 различаются в интерфейсе. Из России OpenRouter
без VPN может отвечать 403.

## Знания в промпте (`features/rag`)

- Запрос строится из последних 15 строк лога (до 1500 символов), очищается на
  телефоне, идёт с тегом ОС (`ubuntu-24.04`).
- Найденное попадает в промпт блоком `<knowledge>`, журнал блоком `<history>`.
  Оба описаны в системном промпте как недоверенные данные. Закрывающие теги в
  содержимом нейтрализуются.
- Документация в `<knowledge>` повторно не очищается: примеры IP из доков
  должны остаться.
- Любая ошибка RAG или журнала не останавливает починку.

## Ошибки

`AppProblem` (+ `AppProblemError`) для настроек и окружения, `LlmFailure`,
`RagFailure`, `SshFailure` для сетевых слоёв. В UI ошибка = локализованная
фраза + технический текст (код, статус, сообщение сервера).
