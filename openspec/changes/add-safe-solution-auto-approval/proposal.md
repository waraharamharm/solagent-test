## Why

Решения «ошибка → исправление», которые присылают пользователи, попадают в ИИ других
пользователей, а тот может предложить их как команды на настоящем сервере. Сейчас
каждое решение одобряется вручную (`python -m solrag.admin approve`). Это не
масштабируется для базы, которая «умнеет раз в сутки». Автоодобрение опасно:
отравленное решение ломает чужие серверы, а модель в роли единственного судьи можно
уговорить одобрить (инъекция промпта) или она пропустит безобидную на вид, но вредную
команду.

Это изменение определяет, когда одобрение может быть автоматическим: только для узкого
класса исправлений с доказуемо низким риском, при независимом подтверждении и с
возможностью отката.

## What Changes

- Клиент присылает **структурированную команду**, которую выполнил (а не только
  свободный текст), и признак того, что весь цикл исправления закончился успехом.
- Сервер сначала работает в **теневом режиме**: считает «одобрил бы автоматически»,
  пишет в лог, но одобряет по-прежнему человек. Автоодобрение включается, только когда
  теневые решения совпадают с решениями человека.
- Решение может быть одобрено автоматически, только если **выполняется всё**:
  1. каждая команда совпадает с коротким **белым списком** (разбор без пайпов,
     перенаправлений, `;`, `&&`, `$(...)`, обратных кавычек, без `sudo`; пути только в
     домашней папке или в названных каталогах конфигов; известные имена сервисов);
  2. оно проходит существующую очистку и проверку на утечки;
  3. то же нормализованное исправление (команда + сигнатура ошибки) пришло **минимум с
     3 разных ключей**, каждому из которых больше 7 дней;
  4. раньше решение с той же сигнатурой не отклонялось и не отзывалось.
- Автоодобренные решения попадают в **карантин**: хранятся с `approval = auto`,
  показываются ИИ как «непроверенные», выводятся в ежедневной сводке для человека и
  отзываются одной командой.
- ИИ-проверка моделью — **дополнительный сигнал**: она может только запретить или
  пометить, но не одобрить сама.

Вне рамок: автоодобрение решений в виде свободного текста, изменение того, что
пользователь видит перед запуском команды (пользователь по-прежнему подтверждает
каждую команду), интерфейс отправки на клиенте.

## Capabilities

### New Capabilities
- `solution-moderation`: правила автоматического одобрения присланного исправления,
  его карантин и откат.

### Modified Capabilities
- нет (модерация описана в `docs/RAG_SERVER.md`, а не в спецификациях).

## Impact

- `rag_server/solrag`: новый `autoapprove.py` (белый список, сигнатура, решение),
  изменения в `store.py`, `moderation.py`, `admin.py` (сводка, отзыв по сигнатуре),
  колонки базы `approval`, `signature`, `commands`.
- Клиент: структурированная отправка после успешного исправления (отдельное
  изменение).
- Связано с безопасностью: решает, что могут предлагать ИИ других пользователей.
  Пишет оркестратор, не субагенты.
