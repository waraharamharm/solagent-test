## Context

`POST /v1/solutions` сохраняет `error` и `solution` (свободный текст) как `pending`.
В поиск решение попадает только после `approve` (человек, на сервере). В клиенте уже
есть `CommandPolicy` (запрещённые и опасные команды), и перед запуском любой команды
ИИ спрашивает пользователя.

## Decisions

1. **Структурированный ввод.** Решение несёт `commands: list[str]` (что реально
   выполнилось) и `verified: bool` (повторный запуск исходного скрипта завершился с
   кодом 0). Решения только со свободным текстом остаются на ручной модерации.
   `verified` сообщает сам клиент, поэтому одного его недостаточно.
2. **Белый список, а не чёрный.** Команда принимается, только если после `shlex` это
   одна простая команда из короткой таблицы, например:
   - `mkdir -p <путь>`, `touch <путь>`, `chmod <режим> <путь>` (путь в `~` или
     `/etc/<известное-приложение>/`),
   - `systemctl restart|reload|enable|start <юнит>` для юнита из известного списка,
   - `apt-get install -y <пакет>` для пакета из известного списка.
   Всё с операторами оболочки, `sudo`, `curl`, `wget`, `sh -c`, перенаправлениями,
   масками или незнакомыми аргументами отклоняется. Таблица лежит в коде, меняется
   через ревью и покрыта тестами на обход.
3. **Сигнатура.** `sha256(нормализованная_сигнатура_ошибки + нормализованные_команды)`.
   При нормализации ошибки отбрасываются числа, хэши, пути, время, чтобы одинаковые
   проблемы совпадали.
4. **Независимое подтверждение.** Считаются различные `key_id` для сигнатуры; ключи
   младше 7 дней не учитываются. Порог 3, настраивается.
5. **Карантин и откат.** Новая колонка `approval` (`manual|auto`). Флаг идёт в
   результатах поиска; в промпте клиента автоэлементы помечаются как непроверенные.
   Ежедневная сводка (`admin digest`) перечисляет новые автоодобрения.
   `admin withdraw-signature` убирает сразу все решения с сигнатурой и закрывает ей
   путь к автоодобрению в будущем.
6. **Сначала теневой режим.** `SOLRAG_AUTO_APPROVE=shadow` (по умолчанию) пишет
   решение в таблицу. `on` включает автоодобрение, `off` выключает всё. Включить `on`
   можно, только когда по теневому логу минимум на N случаях нет ни одного «автомат
   да, человек нет».
7. **Проверка моделью только вспомогательная.** Если используется, текст решения
   подаётся как данные в фиксированный промпт, ответ строго JSON
   `{"risk":"low|medium|high","reason":"..."}`. `medium` или `high` блокирует
   автоодобрение и помечает решение для человека. `low` сам ничего не одобряет.
8. **Аудит.** Для каждого автоодобрения хранится набор причин (какие правила
   сработали, какие ключи подтвердили).

## Risks / Trade-offs

- Крошечный белый список одобряет мало исправлений. Это намеренно: он растёт только
  через ревью с новыми тестами.
- Сговор: три ключа от одного злоумышленника. Ключи выдаются вручную, они должны быть
  старше 7 дней; остаточный риск закрывают сводка и карантин.
- Заявление об успехе можно подделать; это лишь одно из нескольких условий.
